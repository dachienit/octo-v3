# UI & Frontend Adapters

The Octo frontend is designed as a reusable set of components and adapters, allowing for easy integration into existing enterprise portals or as a standalone application.

## Frontend Architecture

The frontend is split into two main parts in the monorepo:
- **`web-ui-corp`**: A library of UI components, storage backends, and utilities.
- **`web-app-corp`**: A reference application built using the UI library.

## Key UI Components

All components are built with standard Web Components and TypeScript, ensuring compatibility across frameworks.

- **`ChatPanel`**: The main container for the chat interface.
- **`MessageList`**: Renders the stream of messages, including system, user, and assistant roles.
- **`ThinkingBlock`**: A specialized component for displaying the agent's internal reasoning (Chain of Thought).
- **`ConsoleBlock`**: Renders tool execution logs and shell output.
- **`AttachmentTile`**: Displays uploaded or generated files.
- **`ModelSelector`**: Allows users to switch between different LLM providers and models.

## Client-Side Adapters

The UI communicates with the backend through an **Adapter** pattern.

### `CoreServiceAdapter`
- **SSE Connection**: Manages the Server-Sent Events connection to the `core-service`.
- **Message Routing**: Parses incoming SSE events and updates the UI state.
- **Error Handling**: Handles connection drops and service errors gracefully.

## Custom Message Renderers

Octo supports custom renderers for different types of tool results or messages. This allows you to build rich, interactive experiences (e.g., rendering a chart from a JSON result or an interactive table).

- **`message-renderer-registry.ts`**: Register your custom renderers here.
- **`ArtifactElement`**: A base class for rendering "artifacts" generated by the agent.

## Persistence Backends

The frontend supports multiple storage backends for local state (like user preferences and recent sessions).
- **`indexeddb-storage-backend.ts`**: Uses the browser's IndexedDB for robust, large-scale local storage.
- **`app-storage.ts`**: Provides a unified API for the UI to interact with the chosen storage backend.
