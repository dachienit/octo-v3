Processing:


  1. Assign the current SAP system id value to the return parameter of the EV_SYSTEM_ID.
  2. Assign the function type based on the type of input PO document (IV_APPLICATION) and mode of operation based on the type of input action (IV_ACTION) and IV_CONDITION values.
    1. For Inforecord, the function types are 'INFO_CREAT', 'INFO_CHNG' & 'INFO_COND'.
  3. When the function type is Inforecord create or change, determine the field attributes based on the utility class /RB4R/MM_cl_inforecord=>get_field_attributes
  4. When the function type is Inforecord condition, determine the field attributes based on the control type /RB4R/MM_INFOP.
  5. Based on the determined field attributes, return the all field information with attributes
    1. TABNAME - Name of the table
    2. FIELDNAME - Name of field name
    3. FIELD_DISP - Field is display only
    4. FIELD_CHNG - Field is editable
    5. FIELD_REQD - Field is mandatory
    6. FIELD_OPTN - Field is optional

CALL METHOD /rb4r/mm_cl_api_info_utility=>map_inbound_data



  1. During Mapping of inbound data, the database values are fetched for EINE/EINA/KONP and compared with the inbound data. Then the resulted records are determined using merge of both entities and as per its corresponding X- Structures.


  1. The enhancement section /RB4R/MM_API_INBOUNDX is provided for developing the customer specific logic for the custom fields in each target system.




  1. Incase of any error during inbound mapping, then SAVE operation terminates and error messages returned to ET_RETURN.

    1. Validation of data
    2. Save

CALL METHOD /rb4r/mm_cl_api_info_utility=>validate_data

  2. Depends upon the type of mode, the save operation takes place.

  1. When the background mode is 'X' (IV_BACKGROUND_MODE = 'X' ), then ASynchronous processing takes place by using background job via submit program /RB4R/MM_PUR_INFOREC_API_JOB and spool number is returned in EV_JOB_NAME and  EV_JOB_ID

4.8. 1.4      Maintenance concept

This tool can be easily configured with the help of the custom tables supplied with this product in order to meet requirements of any target system.


These tables can be maintained via either SM30 or the respective custom transactions, /RB4R/MM_INFOC and /RB4R/MM_INFOD.


Currently in this version, the authorization group MCOR required in order to maintain these tables.


4.9. 1.5      Phase out concept

Phasing out this product is pretty straightforward, as it works completely on its own namespace, having all associated objects in a single package. In order to decommission this product, phase-out (technically deletion) transports prepared in CD system have to be imported to the target system.  To completely delete the product from the system, it would require a deletion transport from DC7 system. This deletion transport must include all the objects of the objects for the respective version of the tool.


Please note that if any development or enhancement implemented locally in target system on top of this CD product, all of them have to be removed from the target system before importing the phase-out transports.
