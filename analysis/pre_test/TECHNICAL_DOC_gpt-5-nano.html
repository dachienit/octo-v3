ZABAP_GENERATOR — Technical Design Document

1. Motivation and Key Figures

1.1. Short description and summary of functions

ZABAP_GENERATOR provides a cohesive framework to create and manage ABAP generator artifacts such as generator classes, reports, and packaging logic. It coordinates a central orchestration program with dedicated generator classes and supporting structures to produce consistent generator components from templates. The architecture is extended by a sub-package setup intended for generator ranges and templates, enabling standardized customization and reuse.

1.2. Business problems solved, benefits

The package automates the creation and configuration of ABAP generator artifacts, reducing manual coding effort and ensuring naming consistency across generated elements. By structuring generation tasks across dedicated classes (orchestrator, class handling, and packaging) and by exposing template-driven workflows, it accelerates delivery of generator components, improves maintainability, and supports scalable expansion via its sub-packages for ranges and templates.

2. Functional Description

  • Entry point: a central generator program initiates the generation process and wires together the orchestration components.
  • Orchestrator: ZCL_ABAP_GENERATOR coordinates the overall flow, initializes technical data, sets main attributes, and triggers generator sub-tasks.
  • Packaging: ZCL_ABAP_GENERATOR_PACKAGE builds new packagenames, creates packages, and returns packagename results to the orchestrator.
  • Class generation: ZCL_ABAP_GENERATOR_CLASS reads existing generator classes, creates new class rangetypes, parameters, attributes, and generates class structures and related artifacts.
  • Report generation: ZCL_ABAP_GENERATOR_REPORT handles creation and updates of generator reports, including reading and applying selection data and templates.
  • Data bindings: Interaction with the underlying DDIC structures (tables, structures, data elements and domains) to persist generator configuration, type information, and mappings.
  • Runtime utilities: A function group (ZFG_ABAP_GEN) provides supporting functionality (e.g., helper routines and include wiring) that the generator workflow relies on during execution.

The functional flow centers on instantiation of the generator program, creation and packaging of new generator components, and generation of ABAP generator artifacts (classes, packages, reports) that are persisted into the dictionary and tied to the deployed templates.

3.4. Most important classes

  • ZCL_ABAP_GENERATOR
    • Role: orchestrator for the overall generation workflow. Manages settings, technical data, and the main run sequence.
    • Key methods: set_main_attributes, run_initialization, update_selection, replace_template_string, replace_template_structure, replace_template_table, get_template_packagename, get_package_rangetypes, get_selection_methodname, show_results.
  • ZCL_ABAP_GENERATOR_PACKAGE
    • Role: packaging layer that creates new packagenames and DEVCLASS packaging objects.
    • Key methods: build_new_packagename, create_package, get_new_packagename.
  • ZCL_ABAP_GENERATOR_CLASS
    • Role: handles reading, creating, and updating generator classes; manages class-related rangetypes, attributes, and parameters.
    • Key methods: read_classes, create_classes, update_selection, read_existing_rangetypes, create_seldata_setmethod, create_parameters, create_attributes, generate_class, read_upd_class, delete_attributes, delete_parameters.
  • ZCL_ABAP_GENERATOR_REPORT
    • Role: manages generator reports (read, create, update, and show logic) including template handling and selection logic.
    • Key methods: build_new_reportname, create_report, update_report, read_selection, read_template_report, show_report.
  • ZCX_ABAP_GEN*, ZCX_ABAP_GEN_CLASS_*, ZCX_ABAP_GEN_PACKAGE*, ZCX_ABAP_GEN_REPORT_*
    • Role: Enhancement points for runtime validation, extension of generation steps, and error signaling.

4. Deployment

4.1. Technical Prerequisites & Dependencies

  • The target SAP system must provide the external DDIC objects referenced by this package:
    • Table ZZt_ABAP_GEN and related structures/structures definitions
    • Tables REPOSRC and DD03L (external DDIC interfaces)
    • Include LSVIMTDT and the function group ZFG_ABAP_GEN (and its function modules)
    • The program ZABAP_GENERATOR and supporting classes (ZCL_ABAP_GENERATOR, ZCL_ABAP_GENERATOR_CLASS, ZCL_ABAP_GENERATOR_PACKAGE, ZCL_ABAP_GENERATOR_REPORT) must be available
    • The enhancement framework classes ZCX_ABAP_GEN* (for optional extensions) Should be present to enable extension points if used
  • The environment must support ABAP language level with standard Development Class and DEVCLASS handling for packaging

4.2. Transport Considerations

  • Transport routing is handled through standard SAP change/transport management (SE09/SE10). The document does not include transport IDs.
  • The deployment approach should ensure the entire generator suite (program, classes, reports, and related DDIC objects) is transported in a consistent unit to avoid dictionary or runtime mismatches.

4.3. Local Adaptation

  • Local adaptations may be performed by:
    • Adjusting development class or DEVCLASS packaging choices (via ZCL_ABAP_GENERATOR_PACKAGE and related code)
    • Modifying template-driven behavior through the template mechanism (ZABAP_GENERATOR_TEMPLATES sub-package)
    • Extending via enhancement points (ZCX_ABAP_GEN_*) if required by the customer
  • Any customization that changes generator behavior should follow standard SAP customization practices to avoid impacting out-of-band updates.

4.4. Local Role maintenance

  • Local roles are maintained externally via PFCG; the package does not embed specific role definitions.

4.5. Deletion and Phase-out

  • Inbound where-used could not be confirmed; verify dependencies before phase-out.
  • Phase-out should consider the dependency graph and ensure the ZABAP_GENERATOR program and its generator classes are not used by other development activities.
